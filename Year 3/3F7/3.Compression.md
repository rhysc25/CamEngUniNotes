Assume some i.i.d. distribution
To each source sequence $X^n$ the code assigns a binary sequence $c(X^n)$. Different sequences get different binary sequences. This should be 1-to-1

$c(X^n)$ is the codeword for the source sequence
Let $l(X^n)$ be the length of the codeword assigned to $X^n$, so the number of bits

Expected code length: $E[l(X^n)]=\sum P(x^n)l(x^n)$
We want to minimise this, the mean number of bits

What is the shortest possible expected code length?

$H(X)$ of the source code can be estimated by measuring the frequency of each symbol.
English is not i.i.d., as given the last letter, the probabilities for the next letter change drastically

Naive Compression Code:
Index all the possible length n sequences. The length of codeword for each sequence is the ceiling of $nlog[X]$ where X is the alphabet size

So the expected number of bits/symbol is approximately $log|X|$

We are treating them all as equally likely, but we can do better by recognising that almost all the probability is centred on the typical set.
At most $2^{n(H(X)+\epsilon)}$ $\epsilon-$ typical sequences. This is much much much smaller than the total number of sets

Now let's try giving just them equal length binary codewords
Prefix the codeword with a flag bit to say whether it's in the typical set or not
Therefore, the bits per typical sequence = $ceil[n(H(X)+\epsilon)]+1$

Therefore, the bits per non-typical sequence = $ceil[nlog|X|]+1$
We need this so we are still assigning a distinct codeword to each sequence in $X^n$

The expected code length = $\sum_{x^n \in A_{\epsilon, n}}P(x^n)l(x^n)+\sum_{x^n \notin A_{\epsilon, n}}P(x^n)l(x^n) \leq \sum_{x^n \in A_{\epsilon, n}}P(x^n)[n(H(X)+\epsilon)+2]+\sum_{x^n \notin A_{\epsilon, n}}P(x^n)[nlog|X|+2]$

The total probability of the sequences outside of the typical set is at most $\epsilon$
So the expected code length is at most $n(H(X)+\epsilon)+\epsilon n log|X|+2 = n(H(X)+\epsilon')$
$\epsilon'$ can be made arbitrarily small

We've made pretty much 20% savings!!

Fundamental Limit of Compression:
For n sufficiently large, there exists a code that has one-to-one mapping and expected code length per source symbol:
$E[\frac{1}{n}l(X^n)]\leq H(X)+\epsilon$

Entropy is the fundamental limit of lossless compression!!

However to actually implement this, we would need a huge look up table.

We can compress much more if we exploit dependencies in the text.

Morse code requires two additional symbols for letter space and word space. But can we design a code that allows decoding without these spaces?

A code is called prefix-free or instantaneously decodable if no codeword is the prefix of another
In a prefix-free code, each symbol can be decoded as soon as you come to the end of the codeword corresponding to it

Given a binary code C, the extension code $C^n$ is the code applied symbol-by-symbol to strings
$C(x_1x_2...x_n)=C(x_1)C(x_2)...C(x_n)$
It's uniquely decodable if for every n, each binary string produced by $C^n$ can be produced by a single source string

A code doesn't have to be prefix-free to be uniquely decodable, e.g. $\{a\rightarrow 0, b\rightarrow 01\}$. However we'll focus on prefix-free codes, and want to minimise expected code length

Prefix free codes MUST HAVE CODEWORDS ON THE LEAVES OF THE TREE. Not a connecting node.

If I have an alphabet, and a list of lengths, we can ask whether a prefix-free code with these lengths exist
This is the same as asking whether you can have a tree with those as leaf depths

A full tree of depth $l_{max}$ has $2^{l_{max}}$ leaves
Each codeword of length $l$ leads to a set of $2^{l_{max}-l}$ unusable leaves at depth $l_{max}$
Hence the total number of unusable leaves at level $l_{max}$ for a code with word lengths $\{l_1,l_2,...,l_N\}$ is $\sum_{i=1}^N2^{l_{max}-l_i}$
This sum has to be less than or equal to $2^{l_{max}}$

Divide both sides by $2^{l_{max}}$:
$\sum_{i=1}^N 2^{-l_i}=2^{-l_1}+2^{-l_2}+...+2^{-l_N}\leq 1$
This is Kraft inequality
A binary prefix-free code exists if and only if it holds

In fact, the Kraft inequality is satisfied by any uniquely decodable code

Given a feasible set of codeword lengths, we want to minimise the expected codeword length
The expected codelength is at least the entropy of the source $L\geq H(X)$

So we want to show that $\sum_i l_i P_i \geq \sum_{i=1}^m P_i \log(\frac{1}{P_i})$:
$H(X)-L=\sum_i P_i \log (\frac{2^{-l_i}}{P_i})$
$ln x \leq x - 1$ (equal iff $x=1$)
Use this inequality to prove it

We get equality $H(X)=L$ when $p_i=2^{-L_i}$ for all i
In practice we're creating codewords for blocks of N source symbols
$X^N=(X_1,X_2,...,X_N)$
The average number of code bits per source symbol, $\frac{E[l(X^N)]}{N}\geq \frac{H(X^N)}{N}=H(X)$, assuming they are i.i.d.

Now we want to construct practical codes with expected length close to $H(X)$

Shannon-Fano coding
Since the codeword lengths $l_i$ are integers, a logical way to choose them is $l_i = ceil[\log\frac{1}{P_i}]$
$ceil[x]<x+1$ so $H(X)\leq L<H(X)+1$

We can also show that this satisfies Kraft inequality, so we can construct a prefix-free code with this set of lengths

If entropy is very large, this is a good result, whereas if you have a small entropy, a 1 bit penalty is large.

Properties of an optimal prefix-free code -
* The lengths are ordered inversely with the probabilities, $p_j>p_k$ then $l_j\leq l_k$
* The two least probable symbols have the same length and are on neighbouring leaves in the binary tree

Huffman Coding 
An algorithm that gives you an optimal prefix-free code for a given set of probabilities
1) Take the two least probable symbols in the alphabet. Give the longest codewords, with equal length and differ only in the last digit
2) Combine these two symbols in a single symbol, so with probability that's the sum of the first 2, and repeat

For a source with alphabet of size m, the Huffman algorithm requires m-1 steps of combining

Not a unique coding though, as there are examples of a three way tie for least probable. And also you can just swap the 1s for 0s and 0s for 1s and it still works, but is now a different code
They will all have the same expected code length

For a given set of probabilities, there is no prefix-free code that has smaller expected length than the Huffman code
